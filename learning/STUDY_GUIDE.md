# 双臂叠毛巾：ACT入门学习回顾

整理日期：2026-11-10。本文汇总本工程此前13课及相关概念，供复习和重新运行实验。课程中的数值来自已有单条示范的教学实测，不是标准ACT训练或机器人闭环成功率。

## 1. 当前进度与最终目标

最终目标是：用专家生成仿真示范，训练标准ACT，让模型读取实时相机和关节反馈，独立控制仿真完成毛巾对折。

已实现和学习的部分：

- Newton双臂、布料物理和一次对折专家；Isaac实时窗口、三路RGB采集。
- 单条示范的状态、动作、视频及LeRobot v3结构导出；检查过Parquet和视频回读。
- 教学版全连接网络、ResNet特征、token、注意力、编码器、解码器和CVAE。
- 少量固定训练样本的拟合、时间分段验证、视觉特征干预和模型保存重载。

尚未完成：固定版本标准LeRobotDataset加载兼容性验证、标准ACT训练、ACT接管实时仿真、独立初态与完整任务成功率评价。

> 教学脚本可以帮助理解原理，但不能把教学模型权重直接当成已验证的叠毛巾策略。

## 4. 第一部分：读懂机器人数据（第1～2课）

### 4.1 观测、状态、动作、策略

| 词语 | 含义 | 本工程例子 |
|---|---|---|
| observation 观测 | 策略当前能获取的信息 | 三路画面和实际关节状态 |
| state 状态 | 当前自身状态数值；字段范围由数据约定 | `observation.state`中的16个数 |
| action 动作 | 随后发送的控制目标 | 目标关节角、目标夹爪命令 |
| policy 策略 | 根据观测产生动作的方法 | 轨迹专家，或训练后的网络 |
| demonstration 示范 | 专家操作过程 | 一次对折轨迹 |
| episode | 从初始化到结束的一次尝试 | 一次完整叠毛巾任务 |
| closed loop 闭环 | 执行后读取新观测、再次决策 | ACT持续根据新画面调整动作 |

当前数据16维顺序：

```text
[左臂关节1～7, 左夹爪closed, 右臂关节1～7, 右夹爪closed]
```

下标从0开始，夹爪下标为7、15；0=开，1=关。仿真按开度小于0.1转换为closed。其他维度单位为弧度，1弧度约57.3度。

必须区分：`state[t]`是当前实际值，`action[t]`是随后目标，不是同一量。正确时序是：

```text
读取当前图像和实际状态 → 选择并记录目标动作 → 执行 → 得到下一状态
```

### 4.2 文件格式

| 文件 | 作用 |
|---|---|
| `data/...parquet` | 每帧状态、动作、时间和索引 |
| `videos/observation.images.*/...mp4` | head、left_wrist、right_wrist三路视频 |
| `meta/info.json` | 字段、形状、频率、数据量与路径 |
| `meta/stats.json` | 归一化相关统计量 |
| `meta/tasks.parquet` | 任务文本 |
| `meta/episodes/...parquet` | episode边界、视频偏移和统计 |
| `meta/towel_schema.json` | 动作和状态名称、编码含义 |
| `SUCCESS.json` | 当前采集器的成功及导出检查标记，不等于标准训练API兼容认证 |

原始采集为640×480 RGB、30 Hz。本机此前示范含815条记录，约27.17秒。视频编码为MPEG-4；参考真实数据为AV1，且真实数据存在删帧与时间压缩，不能照搬其时间语义。

### 4.3 一个ACT训练样本

```text
输入：某时刻t的三路图像＋实际状态
标签：[action[t], action[t+1], …, action[t+29]]
```

B表示batch size，K表示预测动作步数，D表示每步动作维度。

| 形状 | 含义 |
|---|---|
| `[B,3,H,W]` | 一路相机的一批图像 |
| `[B,16]` | 当前状态 |
| `[B,30,16]` | 未来动作块 |
| `[B,30]` | 动作填充标记 |

Batch size=8是一次参数更新使用8个样本，不是预测8步，也不是8台机器人。每个样本可来自不同时间或不同episode。

数据末尾不足K步时可以重复最后动作来补齐形状，但需用掩码排除填充损失；不能让动作块跨episode。第813帧只剩2个真实动作时，其余28步都是填充。

第1课练习：对照三路画面找到接近、闭合、抬起、对折、松手；查看左右夹爪曲线。

第2课练习：解释 `[2,30,16]`，并说明为什么输入没有未来画面，但训练标签可以包含未来专家动作。

## 5. 第二部分：网络怎样学习（第3～4课）

### 5.1 全连接层与MLP

全连接层的每个输出都对全部输入做加权求和再加偏置：`y = Wx + b`。权重大小决定不同输入的影响。

输入m维、输出n维且带偏置时，参数量为 `m*n+n`。例如16→64有1088个参数。全连接层不等于整个网络。

第3课的多层感知机MLP：

```text
16 → Linear → 64 → ReLU → Linear → 64 → ReLU → Linear → 480
                                                        ↓
                                                   排为30×16
```

共有36448个参数。ReLU把负数变成0、保留正数，引入非线性。只有线性层连续叠加，可以合并成一个仿射变换；加入非线性才能表达更复杂关系。

### 5.2 训练循环

```python
prediction = model(inputs)             # 前向计算
loss = criterion(prediction, targets)  # 计算与专家的误差
optimizer.zero_grad()                  # 清除旧梯度
loss.backward()                       # 反向传播，计算梯度
optimizer.step()                      # 利用梯度修改参数
```

| 名词 | 含义 |
|---|---|
| parameter 参数 | 可学习的权重和偏置 |
| gradient 梯度 | 参数变化对损失的局部影响 |
| optimizer 优化器 | 利用梯度更新参数的算法，例如Adam/AdamW |
| learning rate 学习率 | 调整参数的步幅尺度 |
| step | 一次参数更新 |
| epoch | 完整遍历一次训练数据 |
| checkpoint | 保存的模型与必要训练/预处理信息 |
| inference 推理 | 用已有参数计算预测 |

反向传播本身不更新参数，优化器step才会。PyTorch默认累积梯度，普通训练每轮需清零。

最简单的梯度下降：`新参数 = 旧参数 - 学习率*梯度`。Adam会结合梯度历史进行更复杂的调整，职责相同。

### 5.3 损失和归一化

- L1：预测与答案逐项相减，取绝对值再平均。
- MSE：差值平方再平均，对较大误差惩罚更重。
- 归一化：例如 `(原值-训练均值)/训练标准差`。推理后要反变换回控制单位。
- 不同损失、不同归一化下的数值不能直接横向比较；损失不是成功率。
- 统计量只用训练样本计算，验证和部署复用相同统计量。示例对接近常量的维度做了标准差下限处理。

第3课只拟合8个固定样本，300次更新，实测归一化MSE约从1.015931降至0.000594。保存并重新加载模型后，预测一致。这不证明模型能看图或闭环折叠。

### 5.4 训练、验证、测试与过拟合

| 数据 | 用途 | 是否根据其答案更新参数 |
|---|---|---|
| 训练集 | 学习参数 | 是 |
| 验证集 | 选配置、选checkpoint、诊断 | 不做参数更新，但参与开发选择 |
| 测试集 | 开发结束后的最终评价 | 不参与参数或模型选择 |

验证常用：

```python
model.eval()
with torch.no_grad():
    prediction = model(validation_inputs)
    loss = criterion(prediction, validation_targets)
```

`eval()`改变Dropout等特定层行为，不会自动关闭梯度或禁止优化器；`no_grad()`避免构建反向计算图。

过拟合：训练样本表现好，新数据表现差。泛化：对合理但未见过的变化仍有效。误差差距并不能单独证明原因是过拟合，还可能是分布差异、缺少观测等。

第4课在同一轨迹前70%选8个训练样本，后30%选8个验证样本，动作块不跨边界。最终训练MSE约0.000111，验证MSE约0.351184。前后折叠阶段不同，只用于认识误差差距，不是正式泛化验证。

正式数据应按完整episode及初始场景分组划分。相邻帧和重叠动作块随机拆分可能造成数据泄漏，虚高验证成绩。

## 6. 第三部分：图像、token和Transformer（第5～9课）

### 6.1 ResNet视觉特征（第5课）

图像输入是RGB像素。卷积使用局部窗口做加权计算，多组卷积产生多个特征通道。特征不一定能逐维用人类词语命名。

本课采用官方ImageNet预训练ResNet-18，使用其224×224中心裁剪及归一化预处理，处理单帧头部图像：

```text
[1,3,224,224]
 → [1,64,112,112]
 → [1,64,56,56]
 → [1,128,28,28]
 → [1,256,14,14]
 → [1,512,7,7]
```

512是通道数，不是512种物体。特征图亮处只是当前通道响应大，不是抓取点、分割图或注意力解释。

全局平均池化把每张7×7特征图变成一个均值，得到512维向量，但失去显式空间布局。ACT需要关注空间位置，教学后续保留7×7网格。

> 224中心裁剪仅用于入门实验，可能丢失边缘抓角信息；正式ACT的预处理需单独确定。

### 6.2 token和投影（第6课）

一个token可以理解为一条固定长度的特征记录。在7×7网格的每个位置取512个通道值，得到49个512维token。

```text
每路49个 × 三路相机 = 147个视觉token
机器人16维状态 → 1个状态token
合计148个token
```

图像512→128和状态16→128投影到教学用统一宽度。视觉token还加入行列位置和相机编码，用于区分来源及位置，输出 `[B,148,128]`。

Token编号：状态0，head 1～49，left_wrist 50～98，right_wrist 99～147。特征网格位置不是互不相关的原图块，卷积感受野会重叠。

拼接token只是整理输入，并未完成信息融合。第6课新增投影未训练，不能解释为有效策略表示。

### 6.3 Q/K/V与注意力（第7课）

- Q（Query）：当前接收方用于读取信息的查询。
- K（Key）：来源的匹配特征。
- V（Value）：实际被汇总的信息。

它们都由数字向量线性投影得到，不是自然语言问题。

```text
Q与全部K算分数 → 缩放 → Softmax → 权重 → 对V加权求和
```

公式：`Attention(Q,K,V) = softmax(QKᵀ/sqrt(d_k))V`。无Dropout的本课中，每行权重非负、和为1。

例：分数 `[0,1,2]` 得到权重约 `[0.0900,0.2447,0.6652]`，对值 `[10,20,40]` 加权得到约32.4045，不是直接选择40。

注意力矩阵的行数是查询数，列数是来源数。观测自注意力为148×148。自注意力的Q/K/V来自同一组token；交叉注意力的Q来自另一组。

多头注意力并行计算多组投影后合并，不代表各头天然分别对应一个相机。权重随输入重新计算，不是固定表；未训练或已训练的高权重都不能单独证明因果重要性。

### 6.4 完整编码器块（第8课）

本课使用后归一化结构，Dropout为0：

```text
X → 自注意力 → 加回X → LayerNorm
                         ↓
                 FFN → 加回FFN输入 → LayerNorm
```

- 残差是逐项相加，不是拼接；形状需兼容，保留原表示并提供直接的梯度路径。
- `LayerNorm(128)`对每个token内部128个数计算统计量，再应用可学习缩放/偏置。与固定的数据集归一化不同。
- 初始缩放1、偏移0时输出均值接近0、标准差接近1；训练后不能保证这一数值。
- FFN为128→256→ReLU→128，分别加工各token，所有位置共享权重，不直接混合不同token。
- 注意力负责token间信息交换，FFN负责token内部加工。

输入输出均为 `[B,148,128]`，内容已改变，可以继续叠加编码器块。本课4头、每头32维，编码器块132480个参数。检查过与相同权重的PyTorch标准层输出一致。

### 6.5 动作查询与解码器（第9课）

30个动作查询是30个可学习的内部位置向量，不是专家动作。它们可固定共享于不同场景，读取不同观测后产生不同输出。

```text
观测token → 编码器 → 148个观测特征（memory）
                              ↑ 被读取
30个动作查询 → 解码器自注意力 → 交叉注意力 → FFN → 输出层
```

| 计算 | 查询数量 | 来源数量 | 每头权重矩阵 |
|---|---:|---:|---|
| 编码器自注意力 | 148 | 148 | 148×148 |
| 解码器自注意力 | 30 | 30 | 30×30 |
| 解码器交叉注意力 | 30 | 148 | 30×148 |

解码特征 `[B,30,128]` 经同一个 `Linear(128,16)` 得到 `[B,30,16]`。该输出层只有 `128*16+16=2064` 个参数，不乘30；同一规则重复处理30个不同输入，计算量和输出数量增加，但权重共享。

本课先仅用观测预测，再用专家动作算损失。动作查询、编码器、解码器和输出层均可获得梯度，但没有优化器更新。不要把“输出形状正确”误认为“动作可用”。

## 7. 第四部分：多模态训练与视觉依赖（第10～11课）

### 7.1 真正更新编码器—解码器参数

第10课选择8个固定样本，冻结ResNet，提前缓存三路特征；训练视觉/状态投影、位置/相机编码、编码器、动作查询、解码器和输出层。

冻结表示该部分只做前向计算，不通过本次训练修改权重。冻结前端仍可训练后端，降低计算成本。

300次更新，归一化动作MSE约从1.358795降至0.001099。已检查主要模块参数更新，以及模型保存重载后预测一致。

模型 `teaching_policy.pt`保存教学网络和归一化配置，不含ResNet文件；重建仍需同一预训练权重。

### 7.2 检查模型是否受视觉特征影响

第11课加载第10课模型，保持状态和参数不变，干预视觉特征：

- 原始输入与重复基线。
- 互换不同时刻的三路图像特征。
- 全部视觉特征清零。
- 打乱49个网格位置的内容，但保留原位置编码。
- 分别清零head、left_wrist、right_wrist特征。

实测：原始输入重复预测不变；清零全部视觉特征后预测变化MAE约0.897940；换其他时刻图像后约0.771537。均为归一化动作空间中的数值。

两种指标不要混淆：

- 预测变化：干预预测与原预测之差。
- 对原标签的误差：干预预测与原专家答案之差。

视觉特征清零不是黑图，位置/相机编码和投影偏置仍存在。更换图像可能与关节反馈不一致，原专家动作不一定是新组合的正确答案。

结论仅为模型对这些特征干预敏感，不证明它识别了毛巾、正确使用视觉或具有泛化能力。某相机干预影响更大，也不是所有任务中更重要的证据。

## 8. 第五部分：ACT的CVAE（第12～13课）

### 8.1 为什么使用潜变量z

类似观测下，示范可能存在抬高、速度、路径等变化。CVAE提供一种学习额外变化的机制。z是未直接记录在数据中的内部变量，不一定每维对应一个可解释的操作属性。

训练时使用当前机器人状态和未来专家动作，通过变分编码器生成潜变量分布参数：

```text
状态＋专家动作 → 变分编码器 → mu、logvar
sigma = exp(0.5*logvar)
z = mu + sigma*epsilon
```

mu为均值，logvar为对数方差；epsilon从标准正态采样。重参数化把随机性放在epsilon中，使梯度仍能通过mu和sigma传播。本课z为32维。

这里的变分编码器不同于融合当前视觉观测的策略编码器。

### 8.2 两条路径

```text
训练：观测＋从专家动作编码得到的z → 动作预测 → 重建误差＋beta*KL
推理：观测＋固定z=0 → 动作预测
```

推理时不需要未来专家答案，也不调用变分编码器。z=0是标准正态先验的中心，不是关节动作全部为0，不一定是当前后验均值，也不是所有动作的平均。

训练读取答案是结构中受约束的潜变量编码，不是把整段专家动作直接复制为输出。压缩与KL约束仍不保证学到有效策略，需要单独评价无答案推理。

### 8.3 重建损失与KL

- 重建损失：预测动作与专家动作的L1。
- KL：后验潜变量分布与标准正态先验的差异。
- beta：控制KL项的相对权重，本课为10；不是所有任务都适用的调参结论。

如果总损失下降主要来自KL变小，动作误差可能没有改善，因此必须分开观察。

第12课随机初始化、只反向传播不更新。已检查无答案推理、固定z重复预测、标准正态与自身KL为0，以及末尾填充动作不影响后验。

### 8.4 真正训练教学CVAE

第13课复用同一批8个训练样本，冻结ResNet及第10课已经学过的观测投影，再训练CVAE及动作生成网络300次。

| 指标 | 初始 | 更新300次后 |
|---|---:|---:|
| 后验采样动作L1 | 0.924070 | 0.018196 |
| KL | 6.984865 | 0.000259 |
| 固定z=0动作L1 | 0.924077 | 0.018356 |

后验曲线使用固定噪声以便比较，并非计算整个分布的期望。实际训练每次采样新噪声。

无答案推理误差下降是有意义的拟合证据，但仍然是同一批训练数据。**不输入答案，不等于没有见过这个样本。** 两条曲线接近及小KL不能单独证明已学到风格，也不能单凭小KL判定后验坍塌。

| 问题 | 答案要点 |

| token拼起来是否已经融合？ | 尚未交换信息，需要注意力等后续计算 |

## 10. 从教学实验走到标准ACT：剩余路线

不必把所有理论学完才开始工程实践。目前应转入三个里程碑：

### A. 标准数据加载和训练

1. 建立独立训练环境，固定LeRobot版本，不直接修改Isaac环境。
2. 用标准LeRobotDataset读取现有数据，验证图像、时间、归一化、动作块及填充。
3. 必要时用标准接口重新导出；“目录类似v3”不等于已验证API兼容。
4. 标准ACT先做小数据拟合，保存、重载并检查无答案推理。

已有一条示范足够开始管线检查，不足以说明泛化。不要因为数据少就跳过加载与训练验证，也不要因为训练误差低就停止评价。

### B. 策略接管固定初态仿真

```text
同步图像/状态 → ACT → 动作反归一化 → 关节重排/夹爪转换
       ↑                                       ↓
       └──────── 新状态 ← Newton执行 ───────────┘
```

当前worker仍调用专家，需要外部策略动作入口。数据的左右夹爪closed排列不同于仿真内部左右关节加末尾夹爪开度，必须显式转换。

30Hz策略与60Hz仿真需对齐；决定预测30步后执行几步再观察，并在reset清空动作缓存。策略模式需要独立任务完成、失败和超时判断，不能依赖专家阶段编号。播放专家录制轨迹不等于闭环策略。

### C. 重复评价、再扩展场景

先验证单工况重复成功率，再采集小范围变化和必要的恢复示范。单纯复制同一轨迹没有新增场景覆盖；当前reset的seed并未自动随机化毛巾。

按完整episode和初态划分训练/验证/测试。评价抓取、掉落、角点对齐、穿透和最终成功率，不能只看面积缩小。当前辅助粒子绑定抓取和运动学机械臂不等于真实摩擦抓取。

## 11. 设备、真机与pi0.5的学习定位

### 11.1 设备与软件环境

CPU用于加载、解码和普通计算；RAM是系统内存；GPU加速网络；VRAM是显存；SSD负责长期存储。硬盘大不能解决显存不足。

模型文件能放进显存不等于能训练，训练还需梯度、优化器状态和激活。当前教学实验用CPU，标准ACT应在现有GPU上从小batch测量，关闭Isaac后离线训练可减少资源竞争。不要仅凭参数量估算实际显存和时延。

环境分别承担物理、渲染、训练职责。推理时测量采集、预处理、网络、动作发送的端到端延迟，而不是只看网络前向耗时。

### 11.2 真机部署

需逐项核对：关节排列、单位、零位、正方向、绝对/增量目标、夹爪实际反馈与命令、相机视野和预处理、控制频率和延迟。

策略输出通过反归一化、限位、限速、插值、超时处理后发送到底层位置控制器。先只读观测和预测，再低速空载、局部抓取，最后完整折叠。仿真辅助抓取与真机接触差异通常需要真实示范适配。

### 11.3 ACT与pi0.5

ACT标准用法主要根据图像和机器人状态生成动作。pi0.5属于视觉—语言—动作模型，还利用文字指令及大型预训练能力。

同一份图像、状态、动作和任务文字可以作为两者的数据来源，但需按各自实现适配字段、尺寸、动作表示、归一化和时间语义。没有证据表明当前这份本地数据已经实际训练过pi0.5。

pi0.5适合从官方预训练模型微调，不应指望一条仿真示范从零建立基础能力。LoRA是冻结大部分基础权重、训练少量附加参数的方法，仍有基础模型的显存成本。硬件门槛随实现和配置变化，实际使用时核对官方文档，不将以前的估计当作本机已验证结果。

建议先跑通标准ACT与仿真闭环，再考虑pi0.5和真机，复用现有数据但不省略接口与评价。
